## 📋 下一步任務（Phase 1~4）

### Phase 1：資料庫初始化（立即）
**預計工時**：1-2 小時

1. NAS 上建立 SQLite 資料庫 `course-consultation.db`
2. 執行 `students-init-114.sql` 導入 210 名學生名冊
3. 測試 SQL 查詢（班級 + 座號 → 驗證姓名是否相符）

**需要確認**：SQLite 在 NAS Docker 環境的建置方式

---

### Phase 2：後端 API 路由（1週）
**預計工時**：20-30 小時

必實現的 API：
- `POST /api/students/validate` — 驗證班級+座號+姓名是否符合名冊
- `GET /api/template/:semester` — 取得指定學期的 JSON 配置檔
- `POST /api/records/:class/:semester` — 儲存學生填寫的回答
- `GET /api/review/status/:class/:semester` — 教師查詢班級狀態列表

**使用語言**：Node.js + Express（已在 NAS Portainer 運行 docker-compose）

**資料庫 Schema**（待設計）：
- `students` — 學生名冊（已可導入）
- `records` — 各次團諮的紀錄表填寫資料（studentsId, semester, responses JSON）
- `templates` — 紀錄表樣板版本控制

---

### Phase 3：PDF 生成引擎（1.5週）
**預計工時**：25-35 小時

1. **初版 PDF**（學生填寫直後）
   - 使用 Puppeteer 將 HTML 樣板 + 填寫資料 → A4 PDF
   - 教師意見欄留白

2. **正式版 PDF**（教師複核後）
   - 教師確認最終判定後重新生成
   - 教師意見欄印出勾選結果

3. **合併匯出**
   - 團體紀錄表（所有學生 PDF 連接）
   - 團體簽到表（座號 1-40 兩欄，嵌入簽名圖）

**工具**：Puppeteer（已確認 NAS 可安裝）
**注意**：AS7004T 雙核 CPU，需限制 Puppeteer 併發數 ≤ 2

---

### Phase 4：教師後端狀態追蹤（1週）
**預計工時**：15-20 小時

教師後端網頁（Tailscale 私人通道存取）：
1. **學生填寫狀態列表**
   - 以學生名冊為資料來源（LEFT JOIN 填寫紀錄）
   - 紅○未填 / 黃●填寫中 / 綠●完成待複核
   - 每 5-10 秒自動更新（前端輪詢 API）

2. **簽名品質檢查**
   - 顯示全班簽名圖，以班級 Tab 分頁
   - 點「重置」→ 學生需重簽
   - 全班檢查完畢點「檢核完畢」→ 進入正式 PDF 生成

3. **個諮規則檢視**
   - 顯示系統自動判定結果 + 觸發原因
   - 老師可手動覆蓋最終判定
