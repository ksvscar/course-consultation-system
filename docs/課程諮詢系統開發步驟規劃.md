# 課程諮詢紀錄系統 開發步驟規劃

依照先前討論的架構（前端表單/簽名畫布 → NAS後端(SQLite+Puppeteer) → Google Drive Service Account），
拆解為以下 13 個階段（含1個未來擴充階段）。每階段列出：**要做的事** / **你需要提供的資料**。

> **專案範圍**：本階段先以「汽車科」為主，暫不推廣至全校其他科系。因此凡涉及「課程地圖」「科系適用範圍」的項目，目前只需準備汽車科版本即可。

## Phase 4｜PDF 生成引擎（Puppeteer 核心）

**要做的事**
- 建立共用 render pipeline：HTML樣板 + 資料 + 簽名圖 → A4 PDF
- 這個引擎會被功能1(個人PDF)、功能3(預覽)、功能4(合併)共用
- **併發數量限制（Job Queue）**：Puppeteer單一實例約吃100~300MB記憶體，批次生成（如兩班合計80份個人PDF）時不可平行全開，需用佇列機制限制同時執行數量。**依你的AS7004T（2實體核心）建議設為2併發**（非泛用建議的3~5，避免CPU搶佔導致單一實例反而更慢），80份約需100~150秒完成，屬背景批次工作不影響學生填表當下體驗

**你需要提供**
- 無需額外資料，此階段主要是工程實作（沿用 Phase 2 的樣板）

## Phase 5｜後端狀態追蹤 / 預覽 / 刪除 / 個諮規則引擎（功能1）

**要做的事**
- 班級學生填寫狀態列表：**以Phase 1匯入的全班名冊(`students`表)為資料來源**（非以送出紀錄為來源），LEFT JOIN當日送出紀錄，讓完全沒填寫的學生也會出現在列表上，狀態顯示**紅色○**（未填寫）／黃色（填寫中，若有暫存機制）／綠色（已完成待複核），**每5~10秒自動輪詢後端API更新**，讓現場老師能即時看到新送出的紀錄與⚠️標示（不用手動刷新），趁其他學生還在填寫時的空檔即時關心⚠️學生
- 點閱 → 開啟該生PDF；刪除 → 清空該生紀錄並重置狀態
- **規則引擎（送出當下即時執行，非AI，條件式判斷）**：學生簽名送出後，依結構化答案自動判定是否建議個別諮詢，寫入 `records.系統建議` + `records.觸發原因`
  - 觸發規則範例：選課流程了解度任一勾選否／課程地圖勾選完全不瞭解／選課滿意度矛盾（同時勾是與否）／困擾科目大量勾選／未來方向自己父母皆填無或不知道
- 狀態列表加入「⚠️建議個諮」標示 + 觸發原因文字，老師可在後端調整為 `教師最終判定`（預設帶入系統建議，可覆蓋）
- **兩階段PDF生成**：
  1. 學生送出當下 → 生成「初版PDF」，**教師意見欄位留白不印**（老師尚未複核）
  2. 老師後端確認/調整`教師最終判定`後 → 系統依確認結果**重新生成「正式版PDF」**，此時教師意見欄才印上勾選結果，比照你原本紙本表格格式
- 狀態燈號建議增加一階：綠(已完成填寫簽名，待複核) → 藍(老師已複核，正式版已生成)
- **團體簽到總表複核流程（新增，送出後、正式生成前的品管關卡）**：
  - 學生簽名送出後進入「等待複核」狀態，前端顯示「請勿關閉此頁」並每3~5秒輪詢後端查詢自身狀態
  - 教師後端提供「團體簽到總表」HTML即時預覽頁（比照簽到表版面，非PDF），可看到全班目前簽名，隨學生送出/重簽自動更新
  - 老師對字跡潦草的學生點「重置」→ 該生狀態設為「需要重簽」，其前端輪詢偵測到後顯示「重簽」按鈕，回到簽名畫布重簽
  - 老師確認整班無誤後點「老師檢核完畢」→ 將所有「等待複核」狀態學生一次標記為「複核完成」（仍在「需要重簽」中的學生不受影響），學生端顯示「完成」按鈕結束流程
  - 此複核完成後才進入Phase 8正式版簽到表PDF生成
- **多班併諮情境（同年級兩班一併團諮，最多約80人）**：
  - 輪詢/SQLite層級無壓力，該規模對NAS而言負擔很小
  - 團體簽到總表複核預覽頁**以班級分頁（Tab）呈現**，「重置」「檢核完畢」等操作以班為單位分開執行，避免混班誤觸

**你需要提供**
- [ ] 教師登入方式偏好（簡單帳密登入？或僅限校內網段存取不需登入？）
- [ ] 確認上述觸發規則的具體門檻（例如「困擾科目大量勾選」的量化標準是幾科以上？）及是否有遺漏的規則情境

## Phase 9｜部署（前端GitHub Pages + 後端NAS via ASUSTOR DDNS）

**要做的事**
- **前端（學生填寫頁）部署到 GitHub Pages**：推送靜態網頁到 GitHub 倉庫的 `gh-pages` 分支，GitHub 自動發佈為 `https://[username].github.io/[repo]`，完全免費、零維運成本
- **後端維持在 NAS Docker**：PDF生成(Puppeteer)、SQLite資料庫、規則引擎、Google Drive上傳
- **對外連線使用 ASUSTOR DDNS**：NAS 原生 DDNS 功能暴露 API 端點（例如 `https://[你的DDNS名稱].myasustor.com/api/...`），GitHub Pages 前端透過此網址呼叫後端 API
  - 需在 NAS 後端 API 設定 **CORS headers** 允許 GitHub Pages 網域跨域呼叫（一次性設定，之後不用改）
  - 安全考量：ASUSTOR DDNS 網址雖公開但實際只有指定班級學生在團諮時段透過 QR Code/老師發放連結才會使用，使用頻率低、風險可控
- 教師管理後端仍走 **Tailscale 私人通道**（不走 DDNS），確保只有授權老師能存取
